# Stage 1 数据源说明与处理边界

> 本文记录原始数据的真实覆盖、字段语义、异常和缺源边界，以及这些事实对中间层处理的约束。它不是完整的中间层规范：计算规则见 `specs/STAGE1_DATA_PROCESSING.md`，历史验收见 `STAGE1_ACCEPTANCE.md`，当前待办见 `../TODO.md`。

## 1. 基本原则

- 以真实文件和字段为准，不只依赖供应商文档；原始 `data/` 始终只读。
- 数据缺失、冲突或无法确认时保留 `NULL`/UNKNOWN 和原因，不用当前状态、固定比例或未来信息猜造历史。
- 下文行数和日期是已核验源版本的快照；最新产物以各表 manifest 为准。

## 2. 主要数据源实际覆盖

| 数据源 | 已核验覆盖 | 使用时的注意事项 |
|---|---|---|
| `trade_cal` | SSE 日历 2018-01-02 至 2026-09-11，共 2,111 个交易日 | 日历覆盖早于行情，不能把日历起点当作行情或上市历史起点。 |
| `stock_basic` | 5,901 条证券快照：上市 5,562、退市 339 | 当前快照用于明确上市/退市日期，不用当前名称、ST 或市场身份回填历史。 |
| `namechange` | 5,907 个文件、14,205 行名称区间 | 用于历史名称和 ST；区间空洞或冲突保持未知，7 个代码无法匹配当前基础表。 |
| `stk_factor_pro` | 2018-06-01 至 2026-09-11，2,012 个日分区 | 提供原始 OHLC、复权因子和厂商复权字段；行情覆盖不从日历起点开始。 |
| `stk_limit` | 2018-01-02 至 2026-09-18，2,116 个日分区、9,866,957 行 | 提供逐股逐日限价；BJ 占位值、未匹配代码和缺失限价不能当作正常可交易证据。 |
| `suspend_d` | 2018-06-01 至 2026-09-11，S=80,103、R=4,489；另有 41,318 条未匹配 BJ 旧代码事件 | S 为停牌、R 为复牌；完整否定判断只限已核验的 SH/SZ 范围。 |
| `limit_list_d` | 2020-01-02 起，U/D/Z 事件 | 不统计 ST，Z 是炸板而非收盘涨停；仅作独立事件，不再作为完整限价来源。 |
| 三张 VIP 财务表 | 36 个报告期分区，2017Q3–2026Q2；部分缺季由非 VIP 接口补充 | 非 VIP 字段较少且只有指定报告类型，不能与 VIP 权限和完整历史混为一谈。 |
| `fina_indicator` | 按股票分文件，样本报告期为 2018Q2–2026Q2 | 没有 `f_ann_date` 或公告时刻；样本范围不代表所有股票的完整覆盖。 |

其他业务目录登记在 `configs/tushare_tables.yaml`。`primary_key: []` 表示主键尚未确认，不表示无需主键。指数目录的本地文件数量和覆盖也可能与原始 README 不同，官方指数口径仍待核验。

## 3. 财务日期、版本与衍生规则

### 公告可见性

- VIP 财务同时保留 `ann_date` 和 `f_ann_date`，有效公告依据日取两者较晚值；只使用较早日期可能让数据提前可见。
- 只有日期、没有可靠时刻时，从依据日之后的下一个 SSE 交易日开始可用，公告当天不能使用。
- `fina_indicator` 只按 `ann_date` 滞后；缺公告日不能用报告期、文件名或当前日期补造。
- 日期超出日历或没有后续交易日时明确标记不可对齐，不能强行映射到最后一个已知交易日。

字段依据：[TuShare 利润表说明](https://tushare.pro/document/2?doc_id=33)。

### 版本与冲突

- 同一股票、报告期和公告日期可能有多条记录，候选键不保证唯一；所有实际版本和来源位置均保留。
- 全量画像曾发现资产负债表 31 组、现金流 2 组、利润表 6 组冲突。金额冲突时，受影响的单季/TTM 为 `NULL` 并标记 `ambiguous`，不按输入顺序或 `update_flag` 任意选值。
- `fina_indicator` 有 9 条字面字符串 `None` 的公告日期，保留原记录并标记 `invalid_announcement`，但不允许进入研究可见集。
- 当前源文件不能证明供应商保存了每次修订前的完整快照，只能对实际存在的版本执行 PIT 控制。

### 单季与 TTM

- 只有配置明确允许的累计字段才能差分；时点余额、EPS 等不能机械差分或四季求和。
- 缺前期季度时不计算单季，缺任一来源季度时不计算 TTM，并保留具体原因。
- 财务构建保留完整历史，不能用行情输出的起止日期截去差分或 TTM 所需前史。

## 4. 历史代码与跨市场身份

- 行情代码均能匹配当前 `stock_basic`，但财务、名称和限价源存在无法匹配的历史代码；没有可靠生效区间时不猜测换码关系。
- 基础表中有 97 只证券没有行情，其中 96 只已经退市。缺行情不等于证券不存在，身份和行情可用性分开表达。
- 北交所等证券可能早于当前 `list_date` 出现报价。保留原始报价，但不据此提前 A 股上市身份或回填当前市场板块。
- 历史代码 `T600018.SH` 等按供应商原样保留，不能因不是六位数字而删除；缺少名称区间时 ST 状态保持未知。

## 5. 价格、停牌与涨跌停

### 价格与收益

- 原始价格不被覆盖，研究复权价为当日原始 OHLC 乘当日 `adj_factor`，不用未来末日因子归一历史。
- `ret_1d` 只连接相邻交易日的有效行情；缺行情后不能跨多个交易日生成所谓一日收益。

### 停复牌

- `suspend_type=S` 表示停牌，`R` 表示复牌；`suspend_timing` 非空表示日内时段，不能误写成全天停牌。
- 日内停牌可采用保守买卖限制，但必须标明这是研究规则，不是“全天没有成交”的事实。
- 停复牌未匹配事件来自 BJ 旧代码；SH/SZ 在已核验范围内可将无事件解释为未停牌，BJ 无匹配事件保持未知。
- 缺行情和停牌是两种事实，不能互相推导。

字段依据：[TuShare 停复牌说明](https://tushare.pro/document/2?doc_id=214)。

### 涨跌停

- 优先使用 `stk_limit.up_limit/down_limit` 与收盘价判断方向，U/D/Z 事件只作独立观测。
- 280 行 BJ 占位限价不参与判断；有报价但缺限价的证券日保持未知，不按固定百分比补造。
- `ft_limit` 属于期货，不能用作股票限价。

字段依据：[TuShare 涨跌停列表说明](https://tushare.pro/document/2?doc_id=298)。

## 6. 当前缺源边界

| 能力 | 缺少的来源 | 当前处理 |
|---|---|---|
| 历史退市整理期 | 整理期起止日期 | 只用真实 `delist_date` 区分退市前后，整理期保持 NULL。 |
| 早期上市交易日年龄 | 2018-01-02 前完整 SSE 日历 | 覆盖内精确计数；老股提供自然日和估算字段，精确值保持 NULL。 |
| 部分单季/TTM | 缺失的原始财务季度 | 只对齐备来源计算，缺失结果留空。 |
| 公告时刻与完整修订档案 | 盘中时间、每次修订前快照 | 使用公告日后下一交易日规则，保留现有版本。 |
| 历史换码与跨市场身份 | 可核验的生效区间 | 保留原始代码和报价，不跨代码或市场猜接历史。 |
| 服务器跨平台验证 | Linux 目标环境实测 | 作为迁移前条件任务，集中见 `../TODO.md`。 |

## 7. 已解除的早期挂起

- **历史名称和 ST**：2026-09 起由 `namechange` 区间派生，三个 `ex_st` 股票池已激活；区间空洞和语义冲突仍为未知。
- **股票每日限价**：2026-09 起使用 `stk_limit`，覆盖 ST；缺失和占位值仍不参与方向判断。

人工黄金数据只验证上述规则，不能冒充真实来源或解除真实数据的缺源边界。

## 8. 与中间层的连接

- `financial_available` 保留财务原字段、原始日期、`record_id` 和来源位置；`version` 只是确定性序号，不是冲突优先级。
- `daily_stock_state` 和 `daily_trade_status` 分开保存事实与规则，UNKNOWN 不转换成可交易结论。
- 各层完整 Schema、主键、行数和哈希以产物 manifest 为准；长期计算口径统一维护在 `specs/STAGE1_DATA_PROCESSING.md`。
