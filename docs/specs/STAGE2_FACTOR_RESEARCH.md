# Stage 2 因子研究技术规范

## 1. 目标与边界

Stage 2 研究“因子在历史截面上是否具有预测能力”，输出因子值、IC、分组收益和相关统计证据。

它不直接决定持仓，不把理论多空收益当作可交易收益，也不提供实盘能力。完整组合、执行和账户回测属于 Stage 3。

## 2. 标准研究流程

```text
编写因子 compute.py → 计算并保存实验 → 隔离评价 → 审核入库 → 正式重建
```

- 因子源码：`research/factors/<factor_id>/compute.py`。
- 实验产物：`factor_research/experiments/<factor_id>/<experiment_id>/`。
- 正式因子定义：`configs/factor_registry.yaml`。
- 正式批处理：`scripts/build_stage2.py`。

新因子无需提前进入正式注册表。源码中的 `SPEC` 是机器可读契约；`formula` 只是说明文本，真正计算由 `compute()` 完成。

## 3. 因子值契约

`compute()` 返回可由 DuckDB 查询的 relation，至少包含 `trade_date`、`ts_code`、`factor_id`、`value`。统一入口补充历史 `stock_name`、校验数据并保存，不要求每个因子重复编写文件逻辑。

每个实验保存一张长表 `factor_values.parquet`，逻辑主键为：

```text
trade_date + ts_code + factor_id
```

实验目录同时保存 `experiment.yaml`、`manifest.json`、代码快照和配置快照。空值、非有限值、重复主键和证据不匹配必须拒绝。

## 4. 时点和标签

- 因子在 T 日只能使用当时已经可见的信息：行情/状态日期不晚于 T，财务 `available_date` 不晚于 T。
- 动量等需要精确端点的因子，两个交易日端点都必须存在。
- 主标签为 T+1 开盘到 T+1+h 开盘的复权收益；收盘到收盘标签只作对照。
- 入场受阻、开盘涨停、出场顺延、退市和数据末端必须分别标记，不能删除困难样本或虚构收益。
- 当前 horizons 和主评价 horizons 以 `configs/factor_research.yaml` 为准。

日常实验和正式构建只计算本次请求的数据。显式 `--verification audit` 时，才额外执行截断重算、整包测试和独立重复构建；这些开发验收证据不作为 standard 使用前提。

## 5. 股票池与预处理

默认主股票池为 `all_a_ex_st_ipo120_ex_bj`。自定义池由 Stage 1 发布，评价时通过 `--universe` 指定，并在池内重新预处理。

标准处理顺序：

1. 按股票池和有效值筛选，不用 0 或未来值填补缺失；
2. 中位数 ±5×MAD 去极值；
3. 截面 z-score 标准化；
4. 按需要执行行业哑变量和 `log_circ_mv` 截面 OLS 中性化；
5. 再标准化并记录 `process_id`、覆盖和异常原因。

行业 UNKNOWN 单列，不能用未来行业回填后冒充 PIT。样本不足时按配置留空并记录。

## 6. 评价口径

- **IC**：每日因子值与未来收益的 Pearson 截面相关。
- **RankIC**：每日截面秩相关，并列值使用平均秩。
- **ICIR/RankICIR**：对应 IC 序列均值除以标准差；重叠前瞻期使用 Newey-West 做显著性修正。
- **分组评价**：按方向调整后的因子排序分组，使用非重叠持有期和多起点，报告组收益、换手、单调性和多空诊断。
- **组绩效**：包括累计/年化收益、Sharpe、最大回撤、Calmar、胜率和盈亏比。
- **相关性**：同口径下面板的相关性用于识别冗余；不同股票池的 z-score 不能直接拼接比较。

评价结果必须区分 `universe_id`、`process_id`、样本模式、horizon、分段和样本内外。分组和多空指标不包含真实交易费用与冲击，不等于账户回测。

## 7. 输出与研究记录

实验默认评价写入：

```text
<experiment>/evaluation/
```

自定义股票池写入：

```text
<experiment>/evaluations/<universe_id>/
```

主要内容包括：

- `summary.json`：主要指标、覆盖、预处理和相关性摘要；
- `report.md`：人工阅读摘要；
- L3 因子值和预处理值；
- L4 每日 IC、分组收益、汇总指标和只增研究日志；
- `manifest.json`：输入、代码、股票池和结果哈希。

默认评价、自定义评价和正式 L3/L4 相互隔离。自定义评价当前不计算正式 peer 相关性；全市场覆盖率报告不能冒充池内覆盖率。

## 8. 入库与版本

`promote_factor.py` 只有在评价证据、源码哈希和准入策略通过，并显式提供 `--approve` 后才写入正式注册表。

注册表以 `factor_id` 为顶层键，每个因子记录版本、类别、输入、公式说明、窗口、方向、单位、生效日和 PIT 说明。当前只允许新增 ID；相同 ID 即使提高版本也会拒绝，不能靠手工删除旧条目绕过版本管理。

入库只更新定义，不复制实验结果到正式 L3/L4。正式产物由 `build_stage2.py` 使用同一逐因子源码重建。

## 9. 样本外与研究纪律

- 默认只研究样本内；2025-01-01 起为锁定样本外。
- 每个因子版本的正式 OOS 必须单独授权，且只能评价一次；看过结果后修改公式或参数必须视为新版本。
- 评价、试用、失败和空结果都保留记录，不能只留下有利试验。
- 人工小样本用于验证公式，真实数据用于检查覆盖和稳定性。
