# Stage 1 数据处理技术规范

## 1. 目标与边界

Stage 1 把 TuShare 原始数据转换成可复用、可追溯、尽量符合历史时点（PIT）的研究数据。

它负责日历、行情、证券状态、交易状态、财务和研究股票池；不负责因子公式、收益评价、策略信号或交易回测。

## 2. 数据和目录

- `data/`：原始供应商数据，只读，不覆盖、不改名、不删除。
- `data_middle/l0/`：原始数据画像和轻量检查。
- `data_middle/l1/`：标准行情、状态与财务数据。
- `data_middle/l2/`：研究股票池和质量报告。
- `verification/stage1/`：构建、质量和重复性证据。

代码不得写死某台机器的绝对路径，路径由 `configs/paths.yaml` 和 profile 决定。

## 3. 分层产物

| 层 | 主要产物 | 作用 |
|---|---|---|
| L0 | `source_profile`、`source_reconciliation` | 记录来源、字段、行数、范围、主键和文件哈希 |
| L1 | `daily_calendar` | 统一交易日及前后交易日关系 |
| L1 | `daily_adjusted_price` | 原价、复权因子、复权价格和日收益 |
| L1 | `daily_stock_state` | 历史名称、ST、上市退市和板块状态 |
| L1 | `daily_trade_status` | 停牌、限价和买卖可行性 |
| L1 | `financial_available` | 按可见日期排列的财务记录 |
| L1 | `quarterly_financial`、`ttm_financial` | 单季和滚动四季度财务数据 |
| L2 | `daily_research_universe` | 默认每日研究股票池 |
| L2 | `custom_research_universe` | 自定义每日研究股票池 |
| L2 | `data_quality_report` | 统一质量检查结果 |

每张正式表都有明确主键、Parquet 数据文件和 `manifest.json`。manifest 记录 Schema、行数、主键、配置、代码、上游和文件哈希。

## 4. 历史时点规则

### 日历与行情

- 滚动窗口按交易日序号，不按文件行数，也不能跳过缺行情日期后“偷连”。
- 原价保持供应商原值；复权价格使用 `raw_price × adj_factor`。
- 收益率使用相邻有效复权收盘价；跨停牌区间必须按既定规则保留或标记，不能静默当作没有变化。
- 原始行情、复权因子和衍生价格分列保存，不能混用。

### 证券身份

- 股票是否 ST、是否上市、是否退市，必须按当日历史状态判断，不能用当前名单回填历史。
- `stock_name` 是展示字段，关联键使用 `trade_date + ts_code`。
- 历史名称来自名称变更区间；无法确认的 ST、板块、换码或整理期状态保持 UNKNOWN/NULL，不猜造。

### 财务 PIT

- 只有公告日期而没有可靠时刻时，公告后的下一交易日才可用。
- 研究日 T 只能使用 `available_date <= T` 的记录。
- 同报告期多版本全部保留；冲突、缺季和非法日期必须有原因，不能简单取最后一条或回填未来值。
- 单季由累计值差分，TTM 由四个有效单季组成；所需季度不齐时结果为空并说明原因。

## 5. 交易状态

- 停牌、无行情、上市前和退市后不能被默认为正常可交易。
- 涨跌停使用逐日真实限价；缺失或占位值表示未知，不按固定百分比补造。
- 事实字段与规则字段分开：先保存价格、限价和状态，再派生 `can_buy`、`can_sell`。
- 未知必须保留为未知。日级收盘或全天信息不能被解释为当日开盘前已知。

## 6. 研究股票池

默认股票池包括 `all_a`、`all_a_ex_st`、`all_a_ex_st_ipo120`、`all_a_ex_st_ipo120_ex_bj`，按每日状态生成，不能按今天的股票名单过滤历史。

自定义股票池使用每日成员关系，至少包含 `trade_date`、`ts_code`。通用构建器补充历史 `stock_name`，并输出 `universe_id`、`is_in_universe`、Parquet 和 manifest。

自定义池可由文件或同一 DuckDB 连接中的 relation 构建。同 ID、同内容可重复构建；内容变化必须使用新 ID，不能静默改写历史口径。

## 7. 质量与复现

- 原始数据只读，派生表主键唯一，Schema 和日期范围符合契约。
- 财务可见日期不得早于允许的公告可见规则。
- 全量真实数据用于发现覆盖和异常，人工小样本用于核对公式与边界。
- 同一输入、配置和代码的独立构建必须语义一致；差异按表、主键和字段定位。
- 失败或中间临时文件不能成为正式产物。
- Stage 1 不读取前向收益标签，也不以未来数据修正历史状态。
